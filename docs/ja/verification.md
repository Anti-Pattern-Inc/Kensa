## 初回実行チェックリスト

実環境で次を数えて、「使える状態か」を判断する(2026-11-02 に、開発用アカウント 1 つとテスト用ワークロードで 2・3・5・6 を実行した。結果は各項目に書いた。1 と 4 は未実施)。

1. **誤った ○ の件数** — 根拠のない ○ が出ていないか。OpenItems と突き合わせる。
2. **仮置き ✗ の件数と、権限不足(`denied`)の内訳** — `status` の確認済み率を見る。*(実施: 37 チェックのうち `ok` 35・`not_enabled` 2・`denied` 0。Macie の誤分類は直した。スキャンの証拠で判定したのは 3 件だけで、残り 304 件は仮置き)*
3. **欠落・重複** — レンズの全 `choice_id` に状態が付き、重複が無いか(`export --format json` の `items` の件数と、W-A Tool の選択肢の総数を比べる)。*(実施: 307 件・重複 0・判定なし 0。ただし項目は W-A Tool から取ったものなので、同じ取得元との比較にとどまる。公式ドキュメントとの突き合わせはしていない)*
4. **質問の回数と所要時間** — 質問カード(最大 30 枚)とビジネス質問 9 問が多すぎないか。「質問が多い」「業務のヒアリングが足りない」は、まだ**仮説**であり、実ユーザー 1〜2 件で確かめる。
5. **`push` の dry-run → `--apply`** — `ChoiceUpdates` の挙動、「None of these」の扱い、`--milestone`。仮置きの警告が期待どおりか。*(実施: 上の表のとおり。仮置きの警告も出た。仮置きを含めて送ると全質問が「回答済み」になり、`precheck` の「未回答 0」が実態を表さなくなる点に注意)*
6. **再実行** — `snapshot` → 再スキャン → `diff` で、人の回答が保持され、悪化だけが出るか。*(実施: `snapshot` → 悪い証拠を `apply` → `diff` で「悪化 1(○→△)」だけが出た。再スキャンで人の回答が保持されるかは、実アカウントでは未実施)*
